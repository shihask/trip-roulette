# Trip Roulette Kerala — Database & API Specification

**Document version:** 1.2
**Date:** 4 November 2026
**Status:** Logical specification for Supabase Postgres (SQL migrations, RLS), Supabase Edge Functions and a Next.js client. Confirm exact SQL during implementation.

**Changes in 1.2**

- No Prisma. Schema, RLS policies, SQL functions and triggers are SQL migrations.
- Trip ownership uses Supabase Auth (`owner_user_id = auth.uid()`, anonymous users included). `guest_session_hash` removed.
- Real RLS policies per table (§7); clients read directly, writes to trip tables go through Edge Functions only.
- `access_information.is_essential` added; `destinations.exclude_when_stale` removed. Stale or missing essential access excludes a destination.
- Added `algorithm_configs` and `rate_limit_counters`.
- API is now Edge Functions plus direct RLS reads (§8).

**Changes in 1.1** (kept): one trip = one recommendation set; routes, cost assumptions and duration rules tables; costs by transport mode with ranges; roulette idempotency key and public code; frozen share snapshots; itinerary days and local times; one error envelope.

---

## 1. Conventions

- Database: Supabase PostgreSQL. Changes only through SQL migrations in `supabase/migrations/`.
- Access: `supabase-js` with the caller's session, so RLS applies. The service role is used only inside Edge Functions.
- Primary keys: UUID (`gen_random_uuid()`).
- Every table has `created_at timestamptz not null default now()`; mutable tables also have `updated_at` (trigger-maintained).
- Timestamps in UTC. `travel_date` and itinerary times are in **Asia/Kolkata**.
- Money: `bigint` paise (`*_minor`) with `currency char(3) not null default 'INR'`. Never floating point.
- Enumerations: Postgres enums (listed per column).
- Public identifiers: slugs for destinations, opaque tokens for sharing. A UUID is never a secret.
- Archive, don't delete, any record referenced by a trip.
- RLS enabled on every table (§7).

**Eligibility rules (see Architecture §5.2):**

- At least one destination-level essential record with status other than `unknown` must cover the travel date (or the 14-day window for flexible dates). Otherwise the destination is **excluded** as unverifiable.
- Any essential record past `review_due_at` ⇒ **excluded** (stale).
- Any essential record with status `closed` covering the date ⇒ **excluded**.
- Essential `restricted` ⇒ eligible with a warning.
- Non-essential records that are stale or missing ⇒ eligible with a warning.

There is no per-destination override. An exception requires a new, date-specific, verified essential record.

## 7. RLS policies

Helper functions (`security definer`, `stable`):

- `is_admin()` — caller is in `admin_users` with `is_active`, role `admin`, and is not anonymous.
- `is_editor()` — as above with role `editor` or `admin`.
- `owns_trip(trip_id uuid)` — `exists (select 1 from trips where id = trip_id and owner_user_id = auth.uid())`.

| Table | `anon` / any `authenticated` | Trip owner | Editor | Admin |
|---|---|---|---|---|
| `districts`, `categories`, `locations` | select where `is_active` | — | select, insert, update | all |
| `destinations` | select where `published` | — | select all; insert, update (not to `published`) | all |
| `destination_categories`, `attractions`, `destination_images`, `destination_costs`, `access_information` | select where parent destination is `published` | — | select, insert, update | all |
| `information_sources` | select when referenced by a published record | — | select, insert, update | all |
| `location_destination_routes` | select where destination is `published` | — | select | all |
| `algorithm_configs`, `duration_rules`, `cost_assumptions` | none | — | select | all |
| `trips` | none | **select** | — | select |
| `trip_recommendations`, `roulette_results`, `trip_itinerary_items` | none | **select** via `owns_trip` | — | select |
| `trip_share_links` | none | **select** via `owns_trip` (not `token_hash`) | — | select |
| `admin_users` | none | — | select own row | all |
| `admin_audit_log` | none | — | select | select |
| `analytics_events`, `rate_limit_counters` | none | — | — | select |

- **No client insert, update or delete policies on trip tables.** Edge Functions write them with the service role after verifying the caller with a user-scoped client.
- Publishing goes through `publish_destination(id)` (admin only), which checks the publish requirements (§9) and sets `published`.
- `trip_share_links.token_hash` is excluded from client reads with a column-limited view or column privileges.
- Every policy is covered by pgTAP tests for each role in the table.

## 8. Interfaces

### 8.1 Calling conventions

- Edge Functions: `POST {SUPABASE_URL}/functions/v1/<name>` (or `supabase.functions.invoke`). The caller's JWT (anonymous or permanent) is sent automatically. All functions validate input with Zod.
- Direct reads: `supabase.from(...).select(...)` under RLS.
- All function errors use the envelope in §9.

### 8.2 Search locations (direct read)

```ts
supabase.from('locations')
  .select('id, name, district:districts(name)')
  .or(`normalized_name.ilike.%${q}%,aliases.cs.{${q}}`)
  .eq('is_active', true)
  .limit(10)
```

Supported towns only (sanitise `q`). A trigram index backs the search.

### 8.4 Read recommendations and spin result (direct reads)

```ts
supabase.from('trips')
  .select('*, trip_recommendations(*, destination:destinations(slug,name,destination_type,district:districts(name))), roulette_results(*)')
  .eq('id', tripId)
  .single()
```

RLS returns the row only to its owner. Used by the recommendations page, the roulette page on reload, and the "Checking your spin…" state.

### 8.5 `spin`

Headers: `Idempotency-Key: <uuid>` (required). Body: `{ "tripId": "uuid" }`.

`201 Created` (new) or `200 OK` (existing, any key):

```json
{
  "resultId": "uuid",
  "publicCode": "TR-8K2Q",
  "recommendationId": "uuid",
  "destinationSlug": "munnar",
  "index": 0,
  "probability": 0.3333,
  "createdAt": "2026-11-04T09:00:00Z"
}
```

Errors: `404 TRIP_NOT_FOUND` (not the caller's), `409 TRIP_STALE` (a destination was archived), `400 IDEMPOTENCY_KEY_REQUIRED`. The default itinerary is generated in the same call.

### 8.6 Trip destination view (direct reads)

The page at `/trip/[tripId]/destination` reads, under RLS: the trip, the chosen recommendation (`route_snapshot`, `cost_snapshot`, `access_snapshot`), `trip_itinerary_items`, and the destination's public data (images, attractions, access information, sources). No function is needed.

### 8.7 `generate-itinerary`

Request: `{ "tripId": "uuid", "departureLocalTime": "06:00" }`. All other inputs come from stored data. Response:

```json
{
  "status": "suggested",
  "items": [
    { "day": 1, "sequence": 1, "kind": "travel", "title": "Leave Kochi", "startLocal": "06:00", "endLocal": "10:00", "notes": "Travel-time estimate; confirm route before departure" }
  ],
  "warnings": ["Opening hours for Tea Museum not verified"],
  "dataAsOf": "2026-10-28"
}
```

`409 SPIN_REQUIRED` before a spin.

### 8.8 Sharing

`create-share-link` — request `{ "tripId": "uuid" }`, response `201`:

```json
{
  "shareLinkId": "uuid",
  "shareUrl": "https://example.invalid/shared/opaque-token",
  "expiresAt": "2026-12-04T09:00:00Z"
}
```

The real URL uses the production domain. The token appears only in this response.

Snapshot fields: destination name, district, type, primary image; start town; travel date; duration; traveller count; transport mode; per-person estimate and included items; itinerary items; oldest essential-access verification date. **Excluded:** user identifiers, budget entered, moods, trip ID.

`revoke-share-link` — request `{ "shareLinkId": "uuid" }` → `204` (owner only).

`get-shared-trip` — request `{ "token": "…" }` with the anon key → `200` with the snapshot, or `410 SHARE_LINK_EXPIRED` for expired or revoked links. Called by the Next.js server when rendering `/shared/[token]`.

### 8.9 `track-event`

Request `{ "eventType": "trip_shared", "tripId": "uuid", "anonymousId": "…", "metadata": {} }` → `202`. Unknown event types or metadata keys are rejected. Callable with the anon key (events before sign-in).

### 8.10 Admin

- Catalogue CRUD: direct table writes under editor/admin RLS policies; audit triggers record changes.
- Publish: `supabase.rpc('publish_destination', { destination_id })` → validates requirements, publishes, returns the list of failures if any. The admin UI then calls `/api/revalidate` on the Next.js app.
- Configuration (`algorithm_configs`, `duration_rules`, `cost_assumptions`): admin role only.

## 9. Error convention

Every non-2xx Edge Function response uses one envelope:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Please check the highlighted fields.",
    "fieldErrors": { "budgetPerPersonMinor": "Budget must be greater than zero." },
    "details": {},
    "requestId": "uuid"
  }
}
```

| Code | HTTP |
|---|---|
| `VALIDATION_ERROR`, `IDEMPOTENCY_KEY_REQUIRED` | 400 |
| `UNAUTHORIZED` | 401 |
| `FORBIDDEN` | 403 |
| `TRIP_NOT_FOUND`, `DESTINATION_NOT_FOUND` | 404 |
| `TRIP_STALE`, `SPIN_REQUIRED` | 409 |
| `SHARE_LINK_EXPIRED`, `TRIP_EXPIRED` | 410 |
| `LOCATION_NOT_SUPPORTED`, `INSUFFICIENT_DESTINATIONS` | 422 |
| `RATE_LIMITED` | 429 |
| `INTERNAL_ERROR` | 500 |
| `PROVIDER_UNAVAILABLE` | 503 |

Never leak stack traces, SQL or secrets.

## 11. Data lifecycle and editorial operations

- Draft and review destinations are not public.
- `publish_destination` requires: description; at least one licensed image with credit; a primary category; suitable durations; essential costs; **at least one current destination-level essential access record**; routes from every active starting town.
- Costs, access records and cost assumptions have sources and review-due dates. `daily-maintenance` lists overdue records for editors. A destination with stale essential access stays browsable (labelled "Access check due") but is not recommended until re-verified.
- Archive rather than delete destinations referenced by trips.
- Audit every catalogue and configuration change.
- Anonymous users, their trips and share links are deleted after the retention period (90 days for trips, 30 for links, pending decision).
